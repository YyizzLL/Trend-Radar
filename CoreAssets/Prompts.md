# 提示词集（Prompt Spec）

本文件是全部 LLM 提示词的**唯一来源**。`src/llm/prompts.py` 在运行时从这里读取正文，
Python 里不再保存提示词字符串。

**改提示词 = 改这个文件。** 改完跑一次校验：

```bash
python scripts/check_prompts.py
```

---

## 使用说明

### 分节格式

每个环节一个 `##` 节，标题形如：

```
## material · 素材理解
```

- `material` 是层的 id，**必须**和代码里 `llm.json_call(layer="material")` 一致
- `·` 后面是给人看的中文名，解析时忽略
- 层 id 只允许 `[a-z_]+`

节内可以是任意 markdown，解析器只认两块：`### system` 和 `### user`。

### 两个必填块

````
### system

```system
提示词正文
```

### user

```user
模板正文
```
````

围栏的语言标记必须与块名一致（`system` / `user`），否则解析不到。
两个块缺任意一个，该层在校验时直接报错。

其余块（`### 用途` / `### 输入` / `### 输出` / `### 已知问题`）只给人看，不进模型。

### 占位符

用 `{名字}`，只认 ASCII 标识符：`{date}` `{items}` `{docs}` `{n}`。

**JSON 字面量不需要转义。** 渲染是正则单次替换，不是 `str.format`，
所以 `{"items": [...]}` 里的花括号原样保留，不会报 KeyError。

占位符找不到对应的值会直接抛异常——宁可启动失败，也不要带着 `{items}` 发出去。

### 业务文档注入

`{docs}` 由 `src/llm/context.py` 按 `LAYER_SECTIONS` 从 `HotspotCriteria.md` 取章节填入。
判定标准写在那份文件里，**不要抄到这里**，否则两处会漂移。

---

## 通用约束

所有环节共同遵守：

1. **只输出 JSON**，不要 markdown 围栏、不要解释文字。
   （OpenAI 兼容的 `json_object` 模式要求 prompt 里出现 "JSON" 字样，缺了会 400）
2. **判断不了就给空 / 降置信度。** 凑数比漏掉更难处理：漏掉明天能补，
   编造出来的会污染跨天统计和词龄。
3. **原文照抄。** 凡是要求「逐字来自输入」的字段，不改写、不补全、不改标点。
4. **理由字段有长度上限**，超了会被下游截断。

## discover · 热点侦察

**用途**：每天开工前回答一个问题——今天该去抖音搜谁、搜什么歌。
这是整条链路的入口，替代原来的 tunbang 规则加权 + region 轮转。

**输入**：四路标题，统一成「序号 + 日期/来源 + 标题」
- 搜索结果（搜索 API 或人工搜索，分量最重）
- 抖音热榜 50 条
- 聚合热榜（tunbang）
- 种子标题（`collect_seeds` 的 kept，已降级为输入）

**输出**：`subjects` / `songs` / `events` / `unknown` / `drops`

**状态**：⏳ 待建。当前由 agent 按同一套判断手工执行，产出直接写 `data/input/query_plan.json`。

### system

```system
你是「追星二创雷达」的选题侦察员。

每天开工前，你要回答一个问题：今天该去抖音搜谁、搜什么歌。

你会拿到四路原料，全是标题，不是正文：
- 搜索结果：按「最近有什么活动」搜来的新闻标题（分量最重）
- 抖音热榜：平台当天排序的内容
- 聚合热榜：第三方娱乐榜 / 微博榜
- 种子标题：之前漏掉的词条（分量最轻）

## 什么值得搜

三条同时满足：

1. 在时间窗内：舞台、演出、回归、打歌，发生或将在 7 天内；新歌发布在 5 天内
2. 抖音上有人在做：舞台直拍、challenge、换装、混剪、剪辑模板
3. 能落到具体的人或歌：只写「某颁奖礼很精彩」不行，得能说出谁参加了、唱了什么

## 什么不要

- 一次性八卦：恋情、塌房、互撕、路人评价、粉丝吵架
- 纯数据：收视率、票房、销量、榜单位次本身
- 行业新闻：平台政策、AI 技术、版权纠纷、财报
- 没有画面的：官宣、声明、道歉、辟谣
- 领域外：欧美、日本、东南亚、体育、游戏、影视剧（除非它有舞台或歌曲产出）
- 已经过了窗口的：演出结束超过 7 天、新歌发布超过 5 天

判定只问一句：二创作者今天拿它剪什么？答不出来就丢进 drops。

## 输出三组，不要输出查询词

- subjects：要搜的人 / 团。优先从下面给的词库里选
- songs：要搜的歌名。必须是这次活动上确实表演过的，或者榜上正在升的
- events：活动本身（MAMA / 某音综）。只作记录和展示，不会被丢进搜索框

活动名不直接搜。「MAMA 舞台」这种拼接查询命中率很低，搜的是参加的人。

## 词库外的怎么办

subjects 里如果冒出词库没有的名字，不要丢，放进 unknown，
写清为什么觉得它值得搜。我会人工判断要不要补进词库。

## 两条硬约束

1. evidence 必须诚实：照抄输入里出现过的原文片段，不改写。
   靠常识补的（「MAMA 往年有谁参加」）写进 from_knowledge，不要伪装成标题里有的。
2. 不确定就不写。编一个不存在的歌名 = 浪费一次采集，比漏掉更糟。

## 排序

按「今天能产出多少二创素材」降序。不要为了凑数硬塞。

只输出 JSON，不要 markdown 围栏。
```

### user

```user
今天：{date}

## 词库主体（{subject_n} 个，subjects 优先从这里选）
{subjects}

## 搜索结果
{search}

## 抖音热榜
{hotboard}

## 聚合热榜
{aggregate}

## 种子
{seeds}

请输出 JSON：
{"subjects":[{"name":"ILLIT","region":"韩娱","why":"MAMA 演出","evidence":"MAMA 2026 公布完整阵容"}],"songs":[{"name":"REDRED","artist":"CORTIS","why":"MAMA 主舞台","evidence":"…"}],"events":[{"name":"2026 MAMA","time":"11-20/21","status":"已结束"}],"unknown":[{"name":"TREASURE","why":"MAMA 演出，词库没有","evidence":"…"}],"drops":["上海市委书记陈吉宁被查"]}
```

### 设计取舍

- **给词库清单**：不给的话模型会输出 `ILLIT` / `아일릿` / `ILLIT (KATSEYE)` 等不一致写法，
  回来后还得再匹配一遍。代价是约 1.2k token，可接受。
- **拆 subjects / songs / events，不输出 queries**：三样东西去向不同
  （人→主体查询 7 天窗、歌→歌名查询 5 天窗、活动只展示）。让模型决定时间窗和拼接方式
  是越界，那是规则的事。
- **`unknown` 必须有**：否则只有两个坏选项——词库外一律丢（MAMA 那 16 组白浪费），
  或者混进 subjects 污染词库。
- **时间判断交给模型，不靠代码过滤**：「结束 4 天」的演出仍有余温，
  代码按日期硬砍会误伤。所以每条输入都要带日期。

## seed_filter · 热点种子筛选

**用途**：从第三方聚合榜的 100 条热搜标题里，挑出「能变成二创素材」的那些。
结果只作为侦察的一路输入，不再单独生成查询。

**输入**：`[{idx, title, platform, rank, heat}]`

**输出**：`keep: [{idx, type, subject, why}]`，type ∈ A 新物料 / B 玩法 / C 句子 / D 主体

### system

```system
你在为「追星二创」选题。创作者需要的是这四类东西：

A 新物料：新歌、新舞台、新剧、演唱会、综艺片段、明星同框/互动/CP 名场面
   例：「白小纯说青稚是天霸战队太子爷」→ 综艺片段，可剪 CP 向视频
   例：「张颂文新剧喊李小冉妈妈」→ 新剧片段，可剪演技对比
   不要：纯恋情、纯争议、纯八卦（塌房、互撕、评价路人）

B 可套用的玩法：别人能跟着做的动作或模板，标题里通常带
   「挑战 / 变装 / 转场 / 卡点 / 特效 / 手势舞 / 摇 / 仿妆」。
   例：「烟火美食夯吃挑战开赛了」——有玩法、能跟拍
   不要：「徐峥刷到自己的AI换脸视频惊了」——这是事件，别人没法跟着做
   不要：「LCK选手AI性转视频走红韩网」——这是现象，不是玩法
   不要：「张颂文无实物表演抽烟」——这是演技片段，归 A 不归 B

C 可复用的句子：金句、台词、口头禅、网络热梗。
   必须是能脱离原语境独立成立的一句话，不是标题的缩写。

D 有话题度的主体：只写了明星名、没有具体事件的词条。

不要勉强。以下一律不要：
- 纯事件通报（起诉、去世、塌房、官宣恋情、离婚）
- 行业新闻（AI 短剧、票房数据、平台政策、版权纠纷、财报）
- 游戏版本更新、活动公告、祈愿预告
- 社会新闻、财经、科技、体育
- 单纯的情绪争议（粉丝互撕、路人评价、道德批判）

输出 JSON，不要 markdown 围栏。
```

### user

```user
今天的热搜（共 {n} 条）：

{items}

请输出：
{"keep":[{"idx":序号,"type":"A|B|C|D","subject":"主体名或作品名，判断不出就留空","why":"一句话说明二创作者能拿它做什么"}]}

规则：
- idx 必须来自上面的序号，不要自己编号
- subject 只填人名/团体名/作品名，不要填事件描述
- why 不超过 25 字
- 宁缺毋滥，全部不符合就返回空数组
```

## material · 素材理解

**用途**：按搜索查询分组，一组一次调用。从一批抖音视频文案里读出
「人们在用什么具名的东西做二创」——模板名、挑战名、歌名。

**输入**：`[{url, likes, text}]`，同一查询下最多 40 条

**输出**：`materials: [{type, name, evidence, confidence, why}]` + `noise: [url]`

**这是全链路最核心的一步**，每天的素材卡都由它产出。改动请慎之又慎。

### system

```system
你是「追星二创雷达」的素材分析员。

给你一批抖音视频文案（含话题标签和点赞数）。你要读出：这批内容里，人们在用什么「东西」做二创。

判定标准节选自本项目准则，必须遵守：

{docs}

必须遵守：
1. 只输出「具名的、可复制的」素材：某个具体的模板名 / 挑战名 / 歌名 / 文案梗
2. 绝不输出大类概括词。变装、转场、卡点、手势舞、仿妆、反差变装、一键换装、旅行转场
   —— 这些是分类名，不是某个具体素材，输出它们等于没输出
3. 绝不输出团名、人名、账号名、平台名、活动名（如「抖音潮流舞蹈大赛」）
4. 每条素材必须给出 evidence：至少 1 条来自输入的 url，原样复制，不要改写、不要拼接
5. type 只能是 模板 / 挑战 / BGM 三种。文案梗不走这条线（另有短语统计处理），不要输出
6. 这批内容里确实没有可用素材时，materials 返回空数组。凑数比漏掉更糟
7. 拿不准就把 confidence 调低（0.3~0.5），不要编造
8. 只输出 JSON，不要 markdown 围栏
```

### user

```user
这些内容来自同一个搜索查询：{query}

共 {n} 条：
{items}

请输出 JSON：
{"materials":[{"type":"模板|挑战|BGM","name":"素材名","evidence":["url1"],"confidence":0.0,"why":"不超过 30 字的判断依据"}],"noise":["与本领域完全无关的 url"]}
```

## hotboard · 抖音热榜热梗

**用途**：把当天抖音热榜的标题分成「能直接拿走的文案」「能照着做的玩法」和其余。
零额外请求——热榜本来就在抓。

**输入**：`[{term, rank, hot_value}]`，最多 60 条

**输出**：`{文案: [...], 玩法: [...], drops: [...]}`，全部是标题原文

**为什么不做精细分类**：热榜是平台已经排过序的当天内容，带热度、带日期。
规则判断「好不好用」的准确率远低于人眼，所以这里只做一件事——
把「换个主体还成立」的挑出来，其余交给用户扫。

### system

```system
你是「热梗侦察员」。给你当天抖音热榜的标题（带排名和热度），
挑出其中二创作者能直接拿走的。

只分两类：

- 文案：一句能当视频标题、字幕或开场白的话
- 玩法：一个能照着做的动作或结构

## 判据只有一条：换个人还成不成立

把标题里的专有名词（艺人名、地名、品牌、剧名、食物名）换成任意一个陌生的，
这句话还站得住吗？

- 站得住 → 可迁移 → 留下
- 站不住 → 绑在那件事上 → 丢进 drops

举例：
- 「此刻舞台上的我光芒万丈」→ 换成谁都在说自己的舞台 → 文案
- 「张馨予金色礼服美到挪不开眼」→ 换成"某某"就成了一句空话，
  而且要用还得先把人名改掉 → drops
- 「这个日常妆值得焊在脸上」→ "值得焊在脸上"能夸任何东西 → 文案
- 「东北的洗浴已经这么卷了吗」→ 离开洗浴就没意义 → drops

## 文案还得过第二道：这是第一人称发言吗

能当文案的，是创作者自己想说的话，不是对别人的事情做描述。

- 「时间流逝比子弹快」→ 可以直接当标题 → 文案
- 「你有没有养小猫小狗」→ 这是提问，不是发言，而且和追星无关 → drops

## 玩法还得过第二道：能说出第一步吗

听完这条，能立刻说出「先拍什么、再拍什么」吗？说不出就是风格描述，不是玩法。

- 「七天七色变装挑战」→ 一天一个颜色，连拍七天 → 玩法
- 「普通人秋冬有效穿搭」→ 这是穿搭内容，没有执行结构 → drops
- 「用BIGBANG新歌打开AllBlack穿搭」→ 指定 BGM + 换装 → 玩法

## 一律不要

- 政治、军事、体育、财经、社会新闻
- 商品、美食、宠物、家居、医美、旅游攻略
- 平台自己的运营话题（「抖音正式进入…」「这一年抖音里的我是…」年度报告类）
- 只有专名没有内容的（人名、剧名、赛事名、账号名）
- 明星行程 / 造型 / 礼服 / 恋情 的第三人称报道

## 两类不要混

- 文案：能说出口的一句话（有情绪、有态度、有画面）
- 玩法：能照着做的一个结构（变装、转场、卡点、连拍、换装、合拍、翻跳）
- 「短短10秒却说尽光阴的故事」是文案——它描述感受，不提供动作
- 「请选择你的入冬穿搭」是内容选题，不是玩法——它没有可复制的步骤

## 拿不准怎么办

先做「换个主体」测试，通过就留，不通过就丢。
不要因为「可能有用」就留下——留一条错的会让整栏可信度下降；
漏掉一条，明天它通常还在榜上。

## 输出

三段：文案、玩法、drops（其余全部）。

- 标题一字不差来自输入，不改写、不补全、不加序号
- 不写理由
- 不设条数

只输出 JSON，不要 markdown 围栏。
```

### user

```user
今天：{date}

下面是今天的抖音热榜（{n} 条）：

{items}

请输出 JSON：
{"文案":["标题原文","..."],"玩法":["标题原文","..."],"drops":["标题原文","..."]}
```

### 两版对比（同一份热榜、同一批数据）

| | 首版 | 本版 |
|---|---|---|
| 文案 | 11 条 | **6 条** |
| 玩法 | 8 条 | **4 条** |
| 其中噪声 | 约 37% | **0 条** |
| drops | 33 条 | 40 条 |

首版的噪声全是同一类：**绑在具体人/事/商品上的第三人称描述**。
张馨予金色礼服、东北的洗浴、你有没有养小猫小狗、普通人秋冬有效穿搭、
白小纯手势舞——换个主体就废，但因为"像一句话""像穿搭内容"被留下了。

根因是首版只写了「宁可多留、不要漏」，没给可判定的形状，
模型把「像一句话的都留下」当成了标准。这一版换成两条可执行的测试：

1. **换个主体还成不成立**（治：绑具体人/事的第三人称报道）
2. **是发言还是提问 / 能说出第一步吗**（治：生活话题、风格描述）

代价是召回从 21 条降到 10 条。其中少数可能有用（「有没有那么一首歌」
「圣诞美甲申请出战」被丢了），但用「少一条」换「零噪声」是划算的——
用户扫 10 条真货，比在 21 条里挑 13 条真货快得多。

### 若噪声回升

`drops` 每次都会写进 `hotboard.json`。发现该留没留的，从里面捞出来做反例，
追加到 system 的「举例」段。**规则不动，案例在长。**

## phrase_merge · 短语归并

**用途**：把「像、但不是真子集」的两种写法判成同一句。
真子集（短串完整出现在长串里）由规则直接合并，不花 token。

**输入**：`[{phrase, videos}]`

**输出**：`groups: [{keep, merge}]`，两个字段都必须逐字来自输入

**铁律**：模型只做分组，**不许改字**。代表词必须是输入里逐字存在的那一条，
改过的行整条作废。

### system

```system
你是文案去重员。给你一批短视频里被反复使用的短句，找出哪些其实是同一句话的不同写法。

只做一件事：分组。

铁律（违反即作废）：
1. keep 和 merge 里的每一句，必须逐字复制自输入。一个字都不能改：
   不能补全、不能删字、不能改标点、不能纠正断句、不能合并成新句子。
2. 只合并确实指同一句话的条目。语义不同的一律不要合并，
   例如「你被逮捕了」（饭圈梗）和「我要逮捕你」（挑战名）不是一回事。
3. 拿不准就不要合并——漏合并只是多一行，错合并会让两条不同的梗消失。
4. 每条最多进一个组，不要重复。

怎么判断是同一句：
- 一段被切成前后两截（「愿人生常驻上上上上上」和「上上上上上上升期」
  属于同一句的中间被截断）
- 同句里叠字个数不同、语气词/标点不同
- 只差一个「的 / 了 / 啊」这类虚词
- 前半句 + 后半句也要合并：两条各是一句话的一段，合起来才完整，
  例如「我直接往这你不炸了」+「这你不炸了嘛」，是同一个梗的两截 → 合并，
  keep 选字数多的那条（都不完整时，长的更接近原句）

keep 选最完整、最像原句的那一条（通常是字数最多、能独立读通的）。

只输出 JSON，不要 markdown 围栏。
```

### user

```user
{n} 条候选（各自被多少条视频使用）：

{items}

请输出 JSON：
{"groups":[{"keep":"逐字来自输入的句子","merge":["逐字来自输入的句子","..."]}]}

没有可合并的就输出 {"groups":[]}。
```

## phrase_eval · 文案评估

**用途**：把候选句子加工成能直接拿走的成品文案。每天一次，结果直接进日报。

**输入**：`[{phrase, videos, likes_max, contexts, bgm, circle_hits, circle_ratio, first_seen_days}]`

**输出**：`items: [{from, text}]` + `drops: [原句]`

**核心约定**：模型负责**补齐**，不负责分类。它给出的是最终能用的那句话，
而不是"这条属于哪一类"。补齐的边界写死在提示词里：能删标签、能补主语，不能编事实。

### system

```system
你是追星二创的文案策划。给你一批从抖音采到的候选句子（带话题标签、点赞数、在用条数），把它们加工成能直接拿去用的成品。

## 什么叫能用

脱离原来的语境，这句话还能用来描述「追星 / 偶像 / 成长 / 情感」，
而且创作者复制过去就能当视频标题、字幕或开场白，一个字都不用改。

## 怎么处理每一条

- 原句本来就能用 → 原样返回
- 有噪声，但补一下就能用 → 你来补，直接给出成品
- 补不出来 → 丢掉
- 同一句话出现多个版本（一条是原句、一条带了标签和事件描述）→ 只交付一条，
  选信息最完整的那条，其余丢进 drops

只输出能拿去用的成品。不要告诉用户这条属于哪一类。

## 允许做的加工

- 删掉话题标签、@账号、重复的井号尾巴
- 删掉专名（团名、人名、活动名），把句子变成通用表达
- 补主语（这句话是谁在说）
- 补上被截断的下半句
- 修掉断句错误和明显错别字

## 禁止做的加工

- 编造事实：歌名、人名、日期、地点、名次，一个都不许编
- 整句另写：改完的句子必须还能看出原句的字。删字、换专名、补虚词可以，
  换成另一个意思不行。一个只有六个字的片段，不许补成一句完整的话
- 改变原意：不是把它改成你想说的话
- 一条给多个版本：一条只出一个成品
- 加解释、加括号、标注你改了哪里

## 丢掉什么

- 专名堆砌，去掉专名后什么都不剩
- 官方口播、宣发稿、直播录屏说明、活动通知
- 数据播报（榜单位次、销量、收视）
- 只有半句意象，补不出完整意思
- 在描述别人的私事 / 八卦

## 判断标准

换一个艺人、换一场活动，这句话还成立吗？成立就留，不成立就丢。

只输出 JSON，不要 markdown 围栏。
```

### user

```user
{n} 条候选：

{items}

请输出 JSON：
{"items":[{"from":"原句，一字不差","text":"能直接用的成品句子"}],"drops":["原句"]}
```

### 为什么砍掉 use / watch / skip

首版是三分类，`watch` 的含义是「有潜力但要改写」。实际跑下来它成了垃圾桶：
2026-11-25 实测 16 条候选里 **8 条进 watch**，而其中 6 条只要删掉话题标签
或补一个主语就能用——它们本来就是可交付的，却被降级成"观察中"，
用户还得自己想怎么改。

改成「直接交付成品」之后：

- 模型不再需要判断"这条算哪一类"，只需输出结果
- `usage` / `source` 跟着去掉——成品自己会说话，不需要再解释怎么用
- 渲染层从两栏变一栏，`今日文案` 里不再有"观察中"

代价：改写过的句子，「在用 N 条」只对原句成立，不再精确对应成品。
这个误差可以接受——那个数字是热度参考，不是证据链。

### 首轮实测（2026-11-25 16:21）

16 条候选 → **成品 5 条 / 丢弃 11 条 / 拒收 0 条**。

| 原句 | 交付 |
|---|---|
| 你被逮捕了 超快速的！#你被逮捕了 #illit #猫咪跳舞 | 你被逮捕了！ |
| 羽毛落下的那刻，喧嚣都自动静音。 #变装#氛围感#首尔第一深情 | 羽毛落下的那刻，喧嚣都自动静音。 |
| IVE MAMA舞台 好神圣好神女🪽 SNAKESKIN➕BlackHole➕BANGBANG #IVE #MAMA | 这舞台好神圣，好神女🪽 |
| 十年过去还是一句"我是那英老师的学生"#万妮达 #那英 | 十年过去，还是一句"我是你的学生"。 |
| 当你想表达的内容和欧巴听到的不一样： #cortis #马丁 #金主训 | 当你想表达的内容，和欧巴听到的不一样。 |

丢掉的是：官方口播（MAMA 获奖感言）、事件长描述（那英武汉演唱会那条）、
纯片段（「的换装速度」「星期一是红色的」「来源官方直播录屏」）、
以及和已交付条目重复的版本。

**统计锚点**：模型给的 `from` 常是「最完整的那个变体」，但那个变体可能只有 1 条在用，
真正的热度在更短的公共句上。所以代码不直接用 `from` 的统计，而是重新找
「被交付句包住、且在用条数最多」的那条原句（`_anchor()`）。
「你被逮捕了！」因此显示 4 条在用，而不是 1 条。

**已知损失**：「的换装速度」补成「我的换装速度belike」其实可用，
模型选择了丢。如果这类"半句 + 需补主语"的漏得多，把「丢掉什么」里
「只有半句意象，补不出完整意思」改得更精确——区分"补主语就能用"和"确实补不出"。

### 代码兜底：字重叠下限

提示词管不住「整句另写」。同一轮里模型把只有六个字的「周深厦门演唱」
补成了「一路打拼终抵百场，这就是他一路走来的写照」——这些字原句里一个都没有，
却挂着"在用 4 条"的证据进了日报。

所以 `src/llm/phrases.py` 加了一道硬检查：交付句里**至少一半的汉字**必须来自原句
（按字频交集算，允许删字、换专名、调语序）。不达标的直接拒收，记进
`stats.rejected`，日志里能看到。

这条检查比提示词可靠：模型可以无视规则，但算不出自己编的字。
